# M10-03 — owner runbook: capture the Lab fixture corpus

Ten to fifteen minutes at the machine with the game installed. Repeat on the
second OS when convenient; the first platform unblocks the parsers.

## Before capturing

1. Log a character in on each installed flavor (retail; the Forever beta if
   installed), with at least three or four addons enabled. Open the keybind
   and macro panels and change one of each so the cache files are fresh.
2. Combat log. The log records every unit near you, not just you, and the
   tool refuses a log that names any other player. Go somewhere you are
   alone in an instance: on retail walk into a legacy raid or old dungeon
   solo; on Forever a low-level dungeon. Type `/combatlog` just before the
   first boss, kill it, type `/combatlog` again. A boss pull is what writes
   `COMBATANT_INFO`; a training dummy never does (reviewer memory,
   **[verify]** here). Before `/combatlog`, turn on Advanced Combat Logging
   (System → Network, location **[verify]**; community documentation says
   `COMBATANT_INFO` and the advanced per-event fields are only written with
   it on; the CVar is reported as `advancedCombatLogging` **[verify]**).
   Record in the findings whether the header line shows
   `ADVANCED_LOG_ENABLED,1`. Your own pet is fine. If the log is still
   `REFUSED` with "unmapped player GUID", someone was in range: redo it, do
   not edit the log. The tool keeps the first 2 000 lines of the *newest*
   `WoWCombatLog*` file. If your client appends to one file across sessions
   rather than starting a new timestamped one (**[verify]**, and record
   which), the head of that file is your *oldest* session, not the boss
   pull: check that the first timestamp in the captured log is from this
   step, and if not, move older logs out of `Logs/` before repeating it. Note in `docs/DATA_SOURCES.md` if the instance log looks thinner
   than expected (12.x restricted logging), and whether Forever wrote one at
   all. `COMBATANT_INFO` lists your exact gear and talents; decide whether
   you are comfortable with that being public before committing.
3. Log out to the character screen (this writes SavedVariables), then exit
   the game. The tool will run with the client open, but the files on disk
   are stale until logout, so close it first.
4. Optional, once per flavor: launch with `-console`, open the console at
   the login screen with the backtick key, run `ExportInterfaceFiles code`
   (flag, key and command from memory, **[verify]**).
   Not captured as a fixture (it is Blizzard's source), but later waves
   read it locally, and its presence exercises `layout`.
5. Collect the strings the tool cannot discover; each goes in as
   `--extra-name "<text>"`: guild and community names, the name part of your
   BattleTag, your real first and last name, your OS username, hunter or
   warlock pet names, and old character names from renames or transfers
   (those leave folders behind).
6. For each alt that tracker addons know about, run
   `/dump UnitGUID("player")` on it and pass the value as `--own-guid`. A
   refusal never prints the GUID, so you cannot read it off the output.

The tool finds character and realm names from the folders under
`WTF/Account/` of every flavor folder in the install, including leftovers
from uninstalled products. It cannot know anybody else's name.

## Capture

```bash
cd ~/path/to/wowlab
git checkout -b m10/03-lab-corpus origin/main
make setup

# macOS
uv run python scripts/lab_capture.py \
  --root "/Applications/World of Warcraft" \
  --out lab/core/tests/fixtures/incoming --dry-run
# Windows (PowerShell)
uv run python scripts/lab_capture.py `
  --root "C:\Program Files (x86)\World of Warcraft" `
  --out lab/core/tests/fixtures/incoming --dry-run
```

`--root` is wherever the install actually lives. Read the dry-run plan, then
run again without `--dry-run`, adding:

- `--kind <folder>=retail --kind <folder>=forever`, with the flavor folder
  names exactly as they appear as the first path segment of the dry run's
  `would write` lines (do not type them from memory;
  the Forever folder name is one of the things this ticket records). Two
  flavors cannot share a kind.
- every `--extra-name` and `--own-guid` from steps 5 and 6.
- `--platform macos|windows` only if the files were last written by a client
  on a different OS from this machine (Wine, a mounted drive). Off macOS and
  Windows the tool insists on it.

`<out>/<platform>` (for you: `lab/core/tests/fixtures/incoming/macos/` or
`…/windows/`) must be empty; another platform's folder beside it is fine.
The tool never deletes, so it refuses to start over a staging folder that
already holds files; clear that folder by hand between runs. With `--reuse-out`
it runs anyway, lists every file it did **not** write this time and exits
non-zero: those are stale copies from an earlier, less-scrubbed run, and
they must be deleted before anything is moved.

The real names are never printed. `--show-map` prints the name → pseudonym
map for your eyes only; never paste that output anywhere. With `--show-map`
on, an exit-2 message about a name that is too short (one character) or
equal to a format keyword (`set`, `bind`, `end`, `ver`, `true`, `false`,
`nil`, `player`) also prints that name; without it the message says only
`a character name (3 characters)`. Fix the `--extra-name` and re-run rather
than pasting the message.

## Reading the output

0. If the tool stops with exit 2 and "a folder … could not be listed" or "a
   Config.wtf or config-cache.wtf could not be read": nothing was captured,
   on purpose, because the identity map would have been incomplete. Close
   the game if it is running (**[verify]** whether a running Windows client
   blocks reads of these files at all), give your terminal access to
   the install folder (macOS: Privacy → Files and Folders / Full Disk
   Access) and re-run. Do not work around it by copying files elsewhere.
1. Read the `identity map:` line (the second line):
   `identity map: N names (A accounts, R realms, C characters, E extra), G own GUIDs, K CVars blanked`.
   A, R, C and E count distinct *names*, not folders: a character name you
   use on two realms counts once, and a name that is also a realm's (or an
   `--extra-name` equal to a folder name) is absorbed by the first category.
   Allow for that, then check R covers every realm folder under any
   `WTF/Account/`, old flavors included, and that nothing you passed is
   missing. G is the number of your GUIDs the tool found: `lastCharacterGuid`
   from each config file (which files carry it is one of the **[verify]**
   findings), your own characters named in a combat log, and `--own-guid`.
   If G is 0, every file holding a GUID of yours will be refused: pass
   `--own-guid`. On the Forever beta G is always 0 (no `lastCharacterGuid`
   in any config file), so `--own-guid` is mandatory for the SavedVariables
   and combat-log stages. K is the length of the deny-list (eight plus every
   `--blank-cvar`), not a count of lines changed; per-file counts are the
   `cvars-blanked: n` cell.
2. `REFUSED` lines, and the "candidates passed over" list: nothing was
   written for that file, which is the safe outcome. The line gives a byte
   offset and a line number, never the text. Never edit an output file to
   make it pass, and never hand-copy a refused file into the corpus. By
   label:
   - `unmapped player GUID`: yours on an alt (pass `--own-guid`), or someone
     else's (choose a different file with `--sv`, or redo the log alone).
   - `account GUID`, `guild GUID`, `community GUID`, `BattleTag`,
     `email address`, `someone else's name on an own realm`: the file holds
     a Battle.net account id (yours or someone else's) or other people. Choose a different addon's file. If your realm's name is
     also a lore word (a zone, a character's surname), this label can fire
     on game text such as `Zone:<realm>`; there is still no override, so
     choose another file, and expect a longer passed-over list.
   - `surviving identity string (…)`,
     `surviving short identity string (whole word or glued)`,
     `identity string not replaced whole`, `unblanked identity CVar`: one of
     your names survived in a casing or position the tool will not rewrite.
     Choose another file. If it is `Config.wtf` and the cause is a character
     or realm whose name (five letters or more) is part of a real CVar name
     (Sound, Camera, Target…), there is no override today: tell the
     conductor, and record the CVar name in the findings.
   - `unreadable (…)`: see step 0.
   - `<path withheld>` with `in path: …` or
     `unsafe path component after scrubbing`: the problem is in the file's
     own path (a realm or character folder the scrub could not make safe).
     Nothing about that file is printed. Choose another character with
     `--character REALM/NAME`, or pass the name as `--extra-name` if it is
     one the folders did not reveal. `destination escapes --out` and
     `a second source file maps to this destination` are refusals of the
     output path, not of the content.
   - Lines in the passed-over list ending `no longer '…' once scrubbed` are
     not refusals: the file's interesting bytes were your name. Nothing to
     do.
   - With `--reuse-out`, every path listed under "were NOT written by this
     run" is a stale copy from an earlier run. Delete it by hand before
     moving anything.
3. `look   CVars to review by eye: …`: open that config file and read those
   lines. If a value names you, a device ("…'s AirPods"), a path with your
   home folder, a realm or a long id, re-run with `--blank-cvar <name>` and
   list the name in the `docs/LAB_FORMATS.md` §5 amendment.
4. `look   Name-Realm-shaped string that is not a pseudonym pair` and
   `look   whisper/invite/target macro line or @Name`: open the reported
   line. Players on realms where you have no character are never refused;
   this note is all you get. Another player's name means drop or swap the
   file (`--sv`). For macros, either accept that the name becomes public or
   delete that macro in game and recapture; read `macros-cache.txt` in full
   anyway, the note does not know every slash command.
5. `look   own realm next to a faction, region or 'Default' word`: expected in
   almost every Ace3, DataStore or auction addon file. Open the first few
   and check that the segment *beyond* that word is not a player
   (`Jaina-US-<realm>` gets only this note).
6. `look   short identity string inside a longer word`: a name of yours under
   five letters sits inside a longer word and was left alone. Almost always
   coincidence (`max` inside `maximum`). Read the line once; if it really is
   your name glued to something, swap the file.
7. `embedded: n` on a row, and the "replacements per pseudonym" summary: a
   count in the hundreds, or any `embedded`, means one of your names is also
   a game word. Run
   `grep -rniE 'lab(char|realm|name|account)|part[b-h]\b' lab/core/tests/fixtures/incoming/`
   and read the hits. CVar names and the client's own TOC directive keys are
   protected from rewriting; other TOC keys, bind lines, macro bodies and
   Lua strings are not. Pseudonyms are always ASCII, so
   `LC_ALL=C grep -rniE '(lab(char|realm|name|account)|part[b-h])[a-z]*[^ -~]' lab/core/tests/fixtures/incoming/`
   must print nothing (BSD and GNU grep both take this; a non-ASCII byte
   glued to a pseudonym means a name's tail survived the scrub).
8. Blanked `SET x ""` lines and the `Lab…` names are scrub artefacts. Do not
   record them as client behaviour in the findings table below. Refusal and
   `look` lines carry offsets only and are safe to paste into the PR;
   `--show-map` output never is.

## Capture set (per flavor)

- `.build.info` (install root) and `<flavor>/.flavor.info`
- `WTF/Config.wtf`
- One account folder: `SavedVariables.lua`, `config-cache.wtf`,
  `bindings-cache.wtf`, `macros-cache.txt`, and any edit-mode cache file
- One character folder: `config-cache.wtf`, `bindings-cache.wtf`,
  `macros-cache.txt`, `AddOns.txt`, `layout-local.txt`, `chat-cache.txt`
- SavedVariables, account and per-character, chosen for shape coverage
  rather than volume (the tool lists candidates by size and depth):
  - the smallest file, and one that is a single scalar assignment if any
  - one large file (several MB; auction, collection or damage-meter addons)
  - one deeply nested profile-style file (an Ace3 addon)
  - one with a big positional array (`-- [n]` comments)
  - one with non-ASCII strings and one with `|c…|r` / `|H…|h` escapes
  - one with negative numbers, long floats and, if any exists, a non-finite
    number (the tool greps for `inf`, `nan`, `#IN`)
  - one `*.lua.bak`
- Three to five `.toc` files: a single-TOC addon, a multi-flavor addon with
  suffixed TOCs, one using bracketed load conditions if any installed addon
  does
- The first 2 000 lines of the combat log from step 2, including the header
  line and at least one `COMBATANT_INFO` record if present

## Review before committing

```bash
grep -rInE '[A-Za-z0-9._%+-]+@[A-Za-z0-9.-]+|#[0-9]{4,}' lab/core/tests/fixtures/incoming || echo clean
grep -rIn "$USER" lab/core/tests/fixtures/incoming || echo clean
# PowerShell: Select-String -Path lab/core/tests/fixtures/incoming -Recurse -Pattern $env:USERNAME
```

The tool already refuses on emails and BattleTags; this is the human check.
A clean `gitleaks` run says nothing about identity: its rules look for
credentials. The repository is public, so read, in every file, for what no
tool can know:

- **Other players.** Friend and ignore lists, guild rosters, whisper and
  chat history, group members in damage-meter segments, auction sellers,
  mail and trade partners, `Name-Realm` strings on any realm. The tool only
  sees a name joined to one of *your* realms by `-`, ` - `, `.`, `|`, `:`,
  `/`, `_` or parentheses; it cannot see separate `name` and `realm`
  fields, a name joined by a space, comma, tab, `~` or prose, a name ending
  in a digit, or a name with no realm at all. Run
  `grep -rn 'Labrealm' lab/core/tests/fixtures/incoming` and read each line
  for a neighbouring real name. Prefer addons that store settings over
  addons that store people.
- **Names of groups.** Guild, community and custom chat channel names
  (`chat-cache.txt`), layout and profile names in the edit-mode file.
- **Macro bodies** (`macros-cache.txt`), read in full: `/w`, `/invite`,
  `/target Name`, and the forms the tool's note does not know (`/pr`, `/cw`,
  `/who`, `/targetexact`, names inside `/run SendChatMessage(…)`).
- **GUID families the tool does not know.** It refuses `Player-` (unless
  yours), `BNetAccount-`, `Guild-` and `ClubFinder-`; those three spellings
  are reviewer memory. `Community-…` and anything else id-shaped passes.
  Record the real spellings you see in `docs/DATA_SOURCES.md`.
- **Every line of every `Config.wtf` and `config-cache.wtf`**, not only the
  ones the tool pointed at: device names, a path containing your home
  folder, a realm that is not yours, club ids, any long id-looking integer.
- **Bare numeric ids** (`bnetIDAccount`, presence ids, `clubId`, guild ids).
  They cannot be detected at the byte level.
- **Encoded or compressed addon blobs** (WeakAuras, Plater, Details,
  AceSerializer, LibDeflate strings). Nobody can inspect them; prefer not to
  capture a file that contains one.
- **Your names in forms the tool does not derive.** Locally, and never
  pasted anywhere: `grep -ri` for each real character and realm name, with
  and without spaces, in lowercase and slug form (`area-52`), and for names
  with diacritics in both composed and decomposed form.
- **Reversal from context.** A realm pseudonym sitting next to a zone or NPC
  name can give the realm away (`"Labrealma, Netherstorm"`). Read the hits
  of the `Lab…` grep from "Reading the output".
- **`.build.info` on the Forever beta**: look at the `Armadillo`, key and
  `Last Activated` columns before committing it.
- TOC `## Author` and `## X-*` fields are third-party and already public
  for addons you downloaded; an addon you wrote carries your name in
  `## Author:` and needs it as `--extra-name` (step 5).

Fixtures have their own `check-added-large-files` ceiling of 16 MB
(`.pre-commit-config.yaml`; everything else in the repository stays at
512 KB), so the multi-MB SavedVariables file this runbook asks for commits
without any exemption. The automatic selection never picks a file over
8 MiB (`--max-sv-bytes`); only a file you name with `--sv` can be larger. A
fixture is never trimmed or split to fit (L8): if a file you want is over
16 MB, leave it out, say so in the PR with its size, and pick a smaller one.

Then move the
files from `incoming/` to `lab/core/tests/fixtures/<platform>/<flavor-kind>/`
(`retail`, `forever`), paste the provenance rows the tool printed into
`lab/core/tests/fixtures/README.md`, and commit:

```bash
git add lab/core/tests/fixtures docs/DATA_SOURCES.md docs/LAB_FORMATS.md
git commit -m "test(lab): real install fixture corpus (M10-03)"
git push -u origin m10/03-lab-corpus
```

## Record the findings

In `docs/DATA_SOURCES.md` → Local game install → Known state, and as dated
amendments at the foot of `docs/LAB_FORMATS.md`:

| Question | Where to look |
|---|---|
| Forever flavor folder name | directory listing of the install root |
| Forever product code | `<flavor>/.flavor.info` line 2 |
| Forever version and build | `.build.info` row whose `Product` matches |
| Forever interface number | in game: `/dump (select(4, GetBuildInfo()))` |
| Forever `WOW_PROJECT_ID` | in game: `/dump WOW_PROJECT_ID` |
| Forever executable name | flavor folder listing / Activity Monitor / Task Manager |
| Which TOC suffix Forever loads | a multi-TOC addon: which file's `## Title` shows in the addon list |
| SavedVariables line endings | `file <name>.lua` or `xxd <name>.lua | head -2` |
| First bytes of a SavedVariables file | same `xxd` output (leading blank line? BOM?) |
| Does Forever write a combat log, and what is in the header line | `Logs/` after step 2 |
| `synchronize*` CVars present | `grep -i synchronize WTF/Config.wtf` |
| TOC directives the scrub tool does not list | any `## Key:` in a captured TOC that is not in `docs/LAB_FORMATS.md` §3 |
| Identity CVars beyond the eight blanked | the `look   CVars to review by eye` lines, and your own read of every config file |
| Real spellings of account, guild and community GUIDs | grep the install locally for `BNetAccount-`, `Guild-`, `ClubFinder-`, `Community-` |

Not represented in the corpus, by design: non-ASCII folder or character names
(pseudonyms are ASCII; M10-06 covers them with a constructed test), and any
realm-valued or account-valued CVar (blanked).
