# M16-45 — owner runbook: the schema-5 capture (about 15 minutes)

The schema-5 addon code is on branch `m16/45-addon-schema5`. It makes the
lab-addon quieter and adds one kind of key binding:

- the "recording in 15 s" chat line prints once per addon version, or
  after a session whose logout write never ran, instead of on every login
  and `/reload`;
- the research probes (`probes` on the spellbook, action-bar and binding
  records, and the six count-only barber-shop events) are recorded only
  after `/wowlab debug on`, from the next `/reload` or login;
- change events only mark a section dirty, and the dirty sections are
  gathered together at most once every 30 s, out of combat, and at logout;
- the `Constants` sweep of the Legacy talents runs once per session;
- a `CLICK <frame>:<button>` key binding is stored, with the action slot it
  presses, when the frame is an action button (an action-bar addon's
  button). Every other `CLICK` binding is counted in `clicks_left_out`, and
  its name is never stored (ADR-0026, amendment of 2026-10-22).

The open question this capture settles is the **[verify]** in that rule:
whether `GetBinding` lists `CLICK` commands at all. It also checks that the
chat line is quiet on the second login, that no probes are written by
default, and that a name you typed never reaches the file.

Nothing here is committed by you. You run the commands and tell the next
session "M16-45 capture done", with the tool's summary lines and the notes
asked for below. An agent commits the fixture under a new root named for
the build (for example `lab/core/tests/fixtures/macos-<build>/`), with its
provenance rows, and reviewers check it before anything is public. If this
file and `lab/addon/README.md` disagree, the README wins.

Each command is meant to be pasted from your wowlab folder. Your install is
`~/Games/World of Warcraft`.

## 1. Get ready (client closed)

```bash
git fetch origin && git switch m16/45-addon-schema5 && git pull && make setup
```

Check the install plan. It should name only paths under
`Interface/AddOns/WowLab/` and an `## Interface:` line that matches your
game:

```bash
uv run wowlab addon install lab --root "$HOME/Games/World of Warcraft" --dry-run
```

Install it. It asks before writing, and `wowlab undo` reverses it:

```bash
uv run wowlab addon install lab --root "$HOME/Games/World of Warcraft"
```

You also need one action-bar addon that makes its own buttons: Bartender4,
ElvUI or Dominos. Install it the way you normally install addons (the Lab
does not install third-party addons). Note which one, and its version from
the AddOns list.

## 2. In game, one character

1. **First login.** The chat line `WowLab: recording in 15 s. ...` should
   print (this is a new addon version for the file). Note whether it did.
2. **The positive case.** With the bar addon's own keybind mode (Bartender4:
   `/bt4` then "Key Bindings"; ElvUI: `/kb`; Dominos: `/kb`), bind one key,
   for example `SHIFT-F9`, to one of **its** buttons that holds a spell.
   Note the key, which bar and button number it is, and the spell on it.
   Leave keybind mode.
3. **The negative case.** Type both lines below in chat, one at a time.
   The first binds a key to a name you make up, standing in for a GSE
   sequence or any text a player types; pick a word that appears nowhere
   else in the game, for example your own invented word. Replace
   `MyMadeUpWord` with it, and note the word for the grep in section 4 only
   (do not put it in any message: the report uses a pseudonym).
   ```
   /run SetBindingClick("CTRL-F9", "MyMadeUpWord") SaveBindings(GetCurrentBindingSet())
   /run SetBindingClick("CTRL-F10", "Minimap") SaveBindings(GetCurrentBindingSet())
   ```
   The second binds a key to a real frame that is not an action button. If
   you use GSE, a GSE sequence keybind is an even better negative case: bind
   one, and note its sequence name the same way (never in a message).
4. **Log out cleanly** (to character select is enough).
5. **Second login** on the same character. The chat line should **not**
   print this time. Note whether it did. Type `/wowlab debug`; it answers
   "debug is off this session, and off from the next /reload or login".
   Note the answer.
6. **Log out cleanly** again, and exit the client.

If the client crashes at login: at character select, untick **WowLab**, and
report the `Error:` line plus the topmost `Interface/AddOns/WowLab/...` file
and line from the crash report. Never paste the whole report anywhere: it
holds your GUID, BattleTag and guild roster. If the crash names
`Actions.lua`, the next login can switch the section off with
`/wowlab skip bindings` typed within the 15 s window (the chat line may not
print; the window is there either way).

## 3. Capture (client closed)

The tool copies files out of the install and replaces your account folder,
your GUID and the CVars that name your account with pseudonyms or blanks.
It never writes to the install. Character and realm names stay as they are
(owner decision, 2026-10-17). Read every line it marks `look`.

```bash
git switch -c m16/45-capture origin/m16/45-addon-schema5
```

Dry run first. With no `--character` it takes the character you played
last:

```bash
uv run python scripts/lab_capture.py --root "$HOME/Games/World of Warcraft" --out lab/core/tests/fixtures/incoming/m16-45 --flavor _classic_beta_ --kind _classic_beta_=forever --sv WowLab.lua --own-guid "$(cat ~/.config/wowlab/own-guid)" --dry-run
```

Then the real run, the same command without `--dry-run`:

```bash
uv run python scripts/lab_capture.py --root "$HOME/Games/World of Warcraft" --out lab/core/tests/fixtures/incoming/m16-45 --flavor _classic_beta_ --kind _classic_beta_=forever --sv WowLab.lua --own-guid "$(cat ~/.config/wowlab/own-guid)"
```

- If the dry run names a flavor folder other than `_classic_beta_`, use
  that name instead in every command. The folder name changes at launch.
- If a run says `REFUSED`, don't edit anything. Paste the refusal; it never
  prints a name.

## 4. Check the negative case yourself (client closed)

Your made-up word must not be in the captured files. Replace
`MyMadeUpWord` with it:

```bash
grep -rl "MyMadeUpWord" lab/core/tests/fixtures/incoming/m16-45 && echo FOUND || echo absent
grep -rl "CLICK Minimap" lab/core/tests/fixtures/incoming/m16-45 && echo FOUND || echo absent
```

Both should print `absent`. If either prints `FOUND`, stop: do not commit,
and report "M16-45: a left-out name is in the file" with no name in the
message.

Then the key binding cleanup, in game whenever convenient:

```
/run SetBinding("CTRL-F9") SetBinding("CTRL-F10") SaveBindings(GetCurrentBindingSet())
```

Stop there and do not commit. Tell the next session "M16-45 capture done",
with the tool's summary lines and:
- the bar addon and its version, and the key, bar, button and spell of the
  positive case (step 2.2);
- whether the chat line printed on the first login and not on the second
  (steps 2.1 and 2.5), and `/wowlab debug`'s answer;
- whether you used GSE for the negative case (say "a GSE sequence", never
  its name);
- the result of the two greps in section 4.

## Optional: one debug session

Not needed to close M16-45. On the same character: log in, type
`/wowlab debug on`, `/reload`, wait 15 s, log out, and capture again into
`lab/core/tests/fixtures/incoming/m16-45-debug`. The file then carries
`debug = true` and `probes`, including a `GetAttribute` probe on
`bindings` that counts the attribute reads of each `CLICK` frame. Type
`/wowlab debug off` and `/reload` afterwards.

## What the next session does with it

An agent moves the scrubbed `WowLab.lua` files into a new fixture root with
a provenance row each. In the provenance row, the made-up word and any GSE
sequence name are never written; the negative case is described as "a
player-typed name (pseudonymised)". It then checks:

- the file is `schema = 5`, has `announced = 5`, and has no `debug` and no
  `probes` (debug off);
- `bindings.list` holds the positive case as
  `{ command = "CLICK <frame>:<button>", action = <slot>, keys = { "<key>" } }`,
  where `<frame>` is the bar addon's own button name and `<slot>` matches
  the button the owner named; or, if nothing `CLICK` is in the list and
  `clicks_left_out` is 0, `GetBinding` does not list `CLICK` commands, which
  is reported to the conductor as the answer (no key-by-key walk is built);
- `clicks_left_out` is at least 2 (the made-up word and `Minimap`), each
  also in `commands_left_out`, and neither name is anywhere in the file;
- `probe.loads` rose across the first schema-5 write.

It grades the reader on the capture (a real-fixture test beside
`lab/core/tests/parser/test_labaddon_schema_5_m16_45.py`, whose records are
constructed until then), resolves the **[verify]** on `GetBinding` and
`CLICK` in `lab/addon/README.md` and `docs/LAB_PLAN.md` §13.1, and records
what it settled in a dated `docs/LAB_FORMATS.md` amendment. M16-46 (the
keybind views) is graded on the same capture.
