# M11-29 — owner runbook: one applied barber-shop change

The code merged (#143). What is left needs you at the game: about ten minutes
and one paid barber-shop change. The question it answers: on the M11-23
capture the barber-shop record still read `recorded_at = "open"` after an
applied change, and had no `chr_model_id`. The addon now records which
barber-shop events actually reach it, so this capture can say why.

The steps and the **reading table** live in `lab/addon/README.md`, "M11-29
capture step" (the table is 12 rows, first one that fits applies, with a
catch-all last). This file is the short version to work from. If the two ever
disagree, the README wins.

## Before you start

- **It costs gold.** Have enough for the price the shop shows on Accept.
- **The colour change is permanent.** `wowlab undo` reverses only the addon
  install, never a barber-shop change. Changing it back is another paid visit,
  and it must come after the capture (a second sit in the same session spoils
  the counts). Beta characters are wiped anyway.
- **Change one colour only.** Do not change the body type: the shop may offer
  it and it would switch the model and its option ids.
- **The addon's saved format changed** (schema 2). The copy installed before
  M11-29 writes schema 1 and none of the new keys, so you must reinstall it.

Throughout, `WOW` is your install folder (the one holding `.build.info`):

```bash
export WOW="/path/to/World of Warcraft"   # the folder that holds .build.info
cd /path/to/wowlab && git switch main && git pull && make setup
```

## 1. Install the current addon (client closed)

```bash
uv run wowlab addon install lab --root "$WOW" --dry-run
uv run wowlab addon install lab --root "$WOW"
```

The plan should show `## Interface: 16001` (or whatever your `.build.info`
gives that day) and only paths under `Interface/AddOns/WowLab/`.

## 2. Log in on one character and check the addon loaded

Wait for the chat line "WowLab: recording in 15 s" to pass. If you do not see
it, WowLab is probably not running (the line can be missed): type `/wowlab`.
If the addon loaded it answers with two lines starting `WowLab:`.

- If nothing answers: check at character select that WowLab is listed, ticked
  and not marked out of date (`docs/handoffs/M11-03.md` §2), then **stop and
  report**.
- If the client crashes at login: untick WowLab at character select, then
  **stop and report** the `Error:` line and the topmost
  `Interface/AddOns/WowLab/...` file and line from the crash report. Never
  paste the whole report anywhere: it holds your character name, GUID,
  BattleTag and guild roster. Do not go on to step 3.

## 3. Sit once and change one colour

Before changing it, note the position of the current swatch and of the one you
pick, counting from 1, left to right, then top to bottom (for example "hair
colour: 7th, then 3rd"). If the barber shop does not open at all, log out,
capture anyway (step 6) and report it; do not redo.

## 4. Accept once

Click Accept once. Do not cancel and do not sit down again. Note whether the
barber shop closed by itself after Accept or stayed open (and how you left it).
After you stand up, **check that the new colour shows on the character**. If
it did not change, say so: the capture then says nothing about the applied
event.

## 5. Log out in the same session

No `/reload` between the visit and the logout, and do not log that character in
again before you capture: a `/reload` or a second login re-saves the file with
a carried record and zero counts. Exiting from character select is fine.
Exit the client (the file is only complete after logout).

## 6. Capture (client closed)

The capture tool never writes to the install and pseudonymises every name it
finds. One run, on one branch:

```bash
git switch -c m11/29-barber-capture origin/main

uv run python scripts/lab_capture.py --root "$WOW" \
  --out lab/core/tests/fixtures/incoming/m11-29 \
  --flavor _classic_beta_ --kind _classic_beta_=forever \
  --sv WowLab.lua \
  --own-guid "$(cat ~/.config/wowlab/own-guid)" \
  --character "<First>-<Second>" --dry-run
```

Read the dry run, then run it again without `--dry-run`. `<First>-<Second>` is
the character's folder name under `WTF/Account/<account>/<digits>/`; use the
flavor folder name exactly as the dry run shows it. If a run says `REFUSED`,
do not edit anything: paste the refusal (it never prints a name).

Stop there and do not commit. Tell the next session "M11-29 capture done",
with the tool's summary lines and your notes from steps 3 and 4.
