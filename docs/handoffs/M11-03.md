# M11-03 — owner runbook: install the lab-addon, play, capture

Everything in Wave 2 that does not need the game has merged. What is left
needs you at the machine with the Forever beta installed: about 30–45
minutes of play plus two short terminal runs. A dungeon combat log for the
Wave 1 corpus is at the end; it is optional and independent.

Nothing here is committed by you. You run the commands, then tell the next
session "capture done" (and paste the capture tool's summary, which never
contains a name or GUID). An agent commits the fixtures, and reviewers check
them before anything is public.

Throughout, `WOW` is your install folder (the one holding `.build.info`), for
example:

```bash
export WOW="/path/to/World of Warcraft"   # the folder that holds .build.info
cd /path/to/wowlab && git switch main && git pull && make setup
```

## 1. Install the addon (client closed)

> **Update 2026-09-28 (M11-20).** The first install crashed the client about
> 4 s after entering the world: the addon's appearance scan hit an assertion
> inside the client. The fix stops that scan. If you installed before the fix
> merged, close the client, `git pull`, and run the install below again: it
> replaces only the files that changed. For the first login after that, use
> the character that crashed, so any new crash can only come from the
> sections that have not run yet (currencies, professions).

```bash
uv run wowlab addon install lab --root "$WOW" --dry-run
```

Check the plan before going on:

- it shows `## Interface: 16001` (or whatever your `.build.info` gives on the
  day), and every path is under `Interface/AddOns/WowLab/`;
- the source folder it names is this checkout's `lab/addon/WowLab/`.

Then install it for real (it asks before writing; `wowlab undo` reverses it):

```bash
uv run wowlab addon install lab --root "$WOW"
```

## 2. First start: is the addon loading?

1. Start the client. At character select open **AddOns**, pick each
   character you will play (or "all characters") in the drop-down, and check
   **WowLab** is listed and ticked. Note whether it is marked out of date,
   and whether Forever's list has a "load out of date AddOns" option at all.
   If it is marked out of date, stop and report it: the interface number
   wowlab derived does not match this client.
2. Log in. There should be no Lua error. (How to turn on error display on
   Forever is unconfirmed; note what you used.)
3. Type `/dump select(4, GetBuildInfo())`. The number must equal the TOC's
   `## Interface:` value from step 1. Note it.
4. **If the client crashes after you log in** (the Blizzard error reporter
   opens): close it, then at character select open **AddOns** and untick
   **WowLab**, so the next login does not crash too. Report two things from
   the crash report: the `Error:` line and the topmost
   `Interface/AddOns/WowLab/...` file and line in its Lua stack. Never paste
   the whole report anywhere public: it holds your character name, GUID,
   BattleTag and guild names. A crash writes nothing; your previous
   SavedVariables stay as they were and that session's data is lost.

## 3. The play session

Do these in any order that suits you. Each bullet names what it proves; the
full list of open questions is in `lab/addon/README.md` ("M11-03 [verify]
checklist") and `docs/LAB_PLAN.md` §13.1.

- **Every character you have:** log in, then log out (or `/reload`). A crash
  writes nothing, so log out cleanly.
- **One character, twice:** log in, log out, log in, log out. This proves the
  `probe.loads` counter rises.
- **Character sheet:** open it before logging out and note the item level it
  shows (compared with `average.equipped`).
- **Barber shop, no change:** on one character open the barber shop, close it
  without changing anything, log out. Then log in and out **once more
  without** a visit (this proves the record is carried to the next session).
- **Barber shop, one change (optional, costs gold):** apply one change and log
  out. Without it, one question stays open; that is fine.
- **Talents, staged change:** open the talent panel, change a talent **without
  applying it**, and with the panel still open type `/wowlab save`, then
  `/reload`. Note what the panel showed as applied.
- **Below level 25 (if you have such a character):** do this after at least
  one clean capture on a higher-level character; log in and out once.
  Legacy talents show as present with nothing spent (M11-03 finding).
- **Watch for hitches** right after login or `/reload` (the addon rescans
  mounts, toys and pets once per session); note any.
- **After logging out of the last character, exit the client.** The files on
  disk are only complete after logout.

Optional remove check (do it after the capture in step 4, or skip it):
`uv run wowlab addon remove lab --root "$WOW"`, start the client, confirm
WowLab is gone from the list with no broken entry, log in and out, and check
`WowLab.lua` is still there. `uv run wowlab undo` puts the addon back.

## 4. Capture (client closed)

The capture tool copies files out of the install and pseudonymises every
name it finds; it never writes to the install. It takes the account's files
and one character's per run, so run it once per character you played, on
one branch:

```bash
git switch -c m11/03-lab-addon-capture origin/main

uv run python scripts/lab_capture.py --root "$WOW" \
  --out lab/core/tests/fixtures/incoming \
  --flavor _classic_beta_ --kind _classic_beta_=forever \
  --sv WowLab.lua \
  --own-guid "$(cat ~/.config/wowlab/own-guid)" \
  --character "<First>-<Second>" --dry-run
```

- Use the flavor folder name exactly as the dry run shows it (it changes at
  launch). `<First>-<Second>` is the character's folder name under
  `WTF/Account/<account>/<digits>/`.
- Add `--extra-name "<text>"` for anything the tool cannot discover: guild or
  community names, your BattleTag's name part, pet names, old character
  names. Add `--own-guid` for each alt whose GUID you know
  (`/dump UnitGUID("player")` in game).
- Read the dry run, then run it again without `--dry-run`. For the second and
  later characters add `--reuse-out`.
- For sv-merge (M11-09) the next session also needs one addon's
  per-character SavedVariables file from two characters; if an addon you use
  stores per-character settings, add `--sv <ThatAddon>.lua` on both runs.
  Skip it if it holds other players' names (the tool refuses such a file
  anyway).
- If a run says `REFUSED`, do not edit anything; paste the refusal (it never
  prints a name) to the next session.

Stop there: do not commit. Tell the next session "capture done", with the
tool's summary lines and your notes from steps 2–3.

## 5. Optional: a dungeon combat log (Wave 1 corpus, part 4)

Only needed to settle whether Forever writes `COMBATANT_INFO` (the M10-13
criterion left open). Independent of the addon.

1. Turn on Advanced Combat Logging (System → Network; location unconfirmed on
   Forever). Dismiss any pet.
2. Go into a low-level dungeon **alone**. Type `/combatlog` just before the
   first boss, kill it, type `/combatlog` again. Log out, exit.
3. Capture only that log, on its own branch:

```bash
git switch -c m10/03-lab-corpus-4 origin/main
ls "$WOW/_classic_beta_/Logs/"        # find the new WoWCombatLog-*.txt
uv run python scripts/lab_capture.py --root "$WOW" \
  --out lab/core/tests/fixtures/incoming \
  --flavor _classic_beta_ --kind _classic_beta_=forever \
  --own-guid "$(cat ~/.config/wowlab/own-guid)" \
  --combat-log "<that file name>" --dry-run
```

   Then without `--dry-run`. If it is refused for another player in range,
   record a new log; only if that is impossible add
   `--pseudonymise-other-players`.

Never paste the log's real file name, date or time anywhere public (a PR,
issue or chat that ends up in the repo); the tool shifts them by a secret
offset, and the real value next to the shifted one reveals it. Tell the next
session only "dungeon log captured".
