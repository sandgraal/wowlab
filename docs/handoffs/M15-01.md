# M15-01 — owner runbook: the schema-4 capture (about 5 minutes per character)

*Done 2026-10-19:* the owner ran this on build 1.60.1.70450 for
Dangling-Participle (an Orc mage) and Sangraal-Sett (an Undead warlock).
Their `WowLab.lua` files are committed under
`lab/core/tests/fixtures/macos-70450/` with provenance rows, and the reader
is graded on them. Both characters are the first body type (`sex_raw` 2),
so `UnitSex` 3 is still unobserved: a capture of a character of the second
body type is still wanted. Run sections 2 and 3 again for one when
convenient. The barber-shop refresh in "Optional extras" is still open.

The schema-4 addon code is on branch `m15/01-addon-identity`. It adds one
section, `identity`: the character's race id, `UnitSex()`'s value, class id
and class file token. What is left needs you at the game: install the
updated addon, log in and out once on each character you want recorded, and
run one capture command per character. No barber shop, no action-bar setup,
nothing that costs gold.

Nothing here is committed by you. You run the commands and tell the next
session "M15-01 capture done", with the tool's summary lines and the notes
asked for below. An agent commits the fixture under a new root,
`lab/core/tests/fixtures/macos-70450/`, with its provenance row, and
reviewers check it before anything is public. What the capture settles is in
`lab/addon/README.md` (the `identity` notes and the API table rows for
`UnitRace`, `UnitSex` and `UnitClass`). If this file and the README
disagree, the README wins.

Each command is meant to be pasted from your wowlab folder. Your install is
`~/Games/World of Warcraft`; the client is at build 1.60.1.70450.

## 1. Get ready (client closed)

```bash
git fetch origin && git switch m15/01-addon-identity && git pull && make setup
```

Check the install plan. It should name only paths under
`Interface/AddOns/WowLab/` (one of them the new `Identity.lua`) and an
`## Interface:` line that matches your game:

```bash
uv run wowlab addon install lab --root "$HOME/Games/World of Warcraft" --dry-run
```

Install it. It asks before writing, and `wowlab undo` reverses it:

```bash
uv run wowlab addon install lab --root "$HOME/Games/World of Warcraft"
```

## 2. In game, once per character

1. **Log in.** Wait for the chat line "WowLab: recording in 15 s" to pass.
   If you never see it, type `/wowlab`; it answers with two lines starting
   `WowLab:`. If nothing answers, stop and report it.
2. **Note, for each character:** its class, its race, and its body type as
   the character-creation screen calls it ("Body 1" or "Body 2", or male or
   female). The next session checks the file's numbers against these.
   Don't translate: `wowlab char show` prints the body type as
   `Enum.UnitSex` numbers it (0 or 1) beside `UnitSex`'s own value (2 or
   3), and the game's own screens may number body types differently;
   settling which is which is part of what this capture is for.
3. **Log out cleanly** (to character select is enough). The file is only
   complete after logout.
4. **Another character?** Log in on it and repeat 1 to 3. Two characters of
   different body types are the most useful pair: they show both `UnitSex`
   values. One character is enough to close the ticket.
5. Exit the client.

If the client crashes at login: at character select, untick **WowLab**, and
report the `Error:` line plus the topmost `Interface/AddOns/WowLab/...` file
and line from the crash report. Never paste the whole report anywhere: it
holds your GUID, BattleTag and guild roster. If the crash names
`Identity.lua`, the next login can switch the section off with
`/wowlab skip identity` typed within the 15 s the addon announces.

## 3. Capture (client closed)

The tool copies files out of the install and replaces your account folder,
your GUID and the CVars that name your account with pseudonyms or
blanks. It never writes
to the install. Character and realm names stay as they are (owner decision,
2026-10-17). Read every line it marks `look`.

```bash
git switch -c m15/01-identity-capture origin/m15/01-addon-identity
```

Dry run first. With no `--character` it takes the character you played
last. Read what it plans to copy:

```bash
uv run python scripts/lab_capture.py --root "$HOME/Games/World of Warcraft" --out lab/core/tests/fixtures/incoming/m15-01 --flavor _classic_beta_ --kind _classic_beta_=forever --sv WowLab.lua --own-guid "$(cat ~/.config/wowlab/own-guid)" --dry-run
```

Then the real run, which is the same command without `--dry-run`:

```bash
uv run python scripts/lab_capture.py --root "$HOME/Games/World of Warcraft" --out lab/core/tests/fixtures/incoming/m15-01 --flavor _classic_beta_ --kind _classic_beta_=forever --sv WowLab.lua --own-guid "$(cat ~/.config/wowlab/own-guid)"
```

For a second character, run the same two commands with
`--character <Name>-<Realm>` (its folder name under `WTF/Account/…/`) and
`--out lab/core/tests/fixtures/incoming/m15-01-b`. Your `own-guid` file
holds one character's GUID: if the second run refuses on an unmapped
player GUID, paste the refusal and stop rather than adding a GUID by hand.

- If the dry run names a flavor folder other than `_classic_beta_`, use
  that name instead in every command. The folder name changes at launch.
- If a run says `REFUSED`, don't edit anything. Paste the refusal; it never
  prints a name.

Stop there and do not commit. Tell the next session "M15-01 capture done",
with the tool's summary lines and, per character:
- its class, race and body type as the game shows them (step 2.2);
- whether anything in chat looked wrong after the 15 s pass.

## Optional extras for a later session

Not needed to close M15-01, and not tested by this capture:
- **The barber-shop refresh.** `identity` gathers again 2 s after
  `BARBER_SHOP_APPEARANCE_APPLIED`. That the event fires is confirmed
  (70425); that `UnitSex` already gives the new body type at that moment is
  **[verify]**. Checking it costs gold and is permanent: change the body
  type once at the barber shop, Accept, wait a few seconds, then log out
  from where you stand, with no `/reload` and no loading screen between
  the Accept and the logout (either would gather `identity` again and the
  check would pass falsely), and capture as in section 3. If the file still holds the old `sex_raw`, the
  gather ran too early (the logout write does not gather again).

## What the next session does with it

An agent moves the scrubbed `WowLab.lua` files (the account one and each
character's) into `lab/core/tests/fixtures/macos-70450/`, with the
`.build.info` and `.flavor.info` of the run if the conductor rules them in,
and adds a provenance row for each. It checks that each character file is
`schema = 4` with an `identity` table holding exactly one of each value and
its `_absent` reason, that `probe.loads` rose across the first schema-4
write, and that `class_file`, `class_id`, `race_id` and `sex_raw` match your
notes. It then grades the reader on the capture (a real-fixture test beside
`lab/core/tests/parser/test_labaddon_identity_m15_01.py`), resolves the
**[verify]** marks on `UnitSex`, `UnitClass` and `UnitRace` in the README's
API table, and records what it settled, including which `UnitSex` value
each body type gave, in a dated `docs/LAB_FORMATS.md` amendment. That
unblocks M15-02 (the dressing-room link), which reads `identity`.
