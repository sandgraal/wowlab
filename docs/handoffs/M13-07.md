# M13-07 — owner runbook: does an edit to `macros-cache.txt` survive login?

About twenty minutes at the machine with the game installed: two logins on
one character, one small edit before each, and a few commands. Nothing here
is committed by you. You run the steps, then tell the next conductor
session "M13-07 test done" with the table at the end filled in. The
conductor writes the result into `docs/LAB_FORMATS.md` §7 as a dated
amendment, and only then is `wowlab macros fix` built, in the form your
result allows (`docs/BACKLOG.md`, M13-07; `docs/LAB_PLAN.md` §15.2).

The question is one the Lab cannot answer by reading files: when the client
is closed and a macro's text is changed in `macros-cache.txt`, does the next
login keep the change, or does the server put its own copy back? The
`synchronizeMacros` CVar may decide it, so the test runs once with it on and
once with it off. Neither value is a safe default to assume; the Forever
capture of 2026-09-22 did not write the CVar at all
(`docs/LAB_FILE_MAP.md`, timing rules).

Every command is pasted from your wowlab folder. Use the flavor you play;
name it in the report. If the install has more than one flavor folder, add
`--flavor <folder>` to `doctor` and `macros list`, as `wowlab install show`
lists it; the `snap` commands take no `--flavor` (a snapshot names its
flavor itself). *Corrected 2026-10-18.*

## 0. Before anything

1. Quit the game client. Battle.net can stay open.
2. Take a snapshot, so the original file can always come back:

   ```bash
   uv run wowlab snap create -m "M13-07 before the macros test"
   ```

3. Record the current sync setting. `doctor` prints the three
   `synchronize*` CVars once for `WTF/Config.wtf` and once for each
   account's `config-cache.wtf`, and the lines can disagree. Write down
   every `synchronizeMacros` line with its file (a value, or "not set
   (client default)"). Which file the client obeys is part of what this
   test finds out:

   ```bash
   uv run wowlab doctor
   ```

4. List the character's macros so you know the file and have a baseline:

   ```bash
   uv run wowlab macros list --character <Character>
   ```

   The file is `WTF/Account/<ACCOUNT>/<Realm folder>/<Character>/macros-cache.txt`
   (character macros) and `WTF/Account/<ACCOUNT>/macros-cache.txt` (account
   macros). Use the character file. If the character has no macro yet,
   make one in game first (`/macro`, New, a `/say` body), log out, and come
   back to this step.

## 1. Run A: with `synchronizeMacros` as it is now

1. With the client closed, open the character's `macros-cache.txt` in a
   plain text editor (not Word; TextEdit in plain-text mode, Notepad, or
   `nano`). Keep the line endings the file already has.
2. Pick one macro and change its body in a way you will recognise, for
   example add ` M13-07` to the end of a `/say` line. Change nothing else:
   not the `VER` line, not the name, not the `END` line. Save.
3. Note the file's modification time now (`ls -l` on macOS/Linux, the
   Properties dialog on Windows). You will compare it after logout.
4. Start the game, log in on that character, open the macro panel
   (`/macro`) and look at the macro you changed. Write down whether the
   panel shows your edit.
5. Log out to the character list, then quit the client fully. The caches
   are written at logout, so an offline look before this sees the old
   session.
6. With the client closed, open the file again. Write down: is your edit
   still there; did the modification time change at logout.

   `wowlab macros list --character <Character>` shows the bodies too, if
   you prefer not to read the file.

## 2. Flip the CVar, then run B

1. Start the game, log in on the same character, and in the chat box set
   the CVar to the opposite of what `doctor` reported for the account's
   `config-cache.wtf`, then log out and quit. If it showed `1`, type:

   ```
   /console synchronizeMacros 0
   ```

   If it showed `0`, type `/console synchronizeMacros 1` instead. If it
   showed "not set (client default)", treat run A as the default, do run B
   with `0`, and, if you have time, a run C with `1`.

2. Confirm the file now records the new value:

   ```bash
   uv run wowlab doctor
   ```

3. Repeat section 1, steps 1 to 6, with a different recognisable edit
   (for example ` run B` instead of ` M13-07`).

## 3. Put things back

If the edit persisted, change the macro back in game, or restore the file:

```bash
uv run wowlab snap list
uv run wowlab snap restore <id> --paths "WTF/Account/<ACCOUNT>/<Realm folder>/<Character>/macros-cache.txt"
```

Set `synchronizeMacros` back to what `doctor` showed in step 0.3 (in game,
`/console synchronizeMacros <value>`), unless you prefer the new value.

## 4. What to report

One row per run. Values are what you saw, not what you expected.

| Run | `synchronizeMacros` (every line `doctor` prints, with its file) | Edit shown in `/macro` after login? | Edit still in the file after logout? | File mtime changed at logout? | Flavor, client build (`doctor` prints both) |
|---|---|---|---|---|---|
| A | | | | | |
| B | | | | | |
| C (optional) | | | | | |

Also say:
- whether the file's line endings were LF or CRLF (the editor usually says;
  `file macros-cache.txt` on macOS/Linux says "with CRLF line terminators"
  when they are), and whether that changed after logout;
- whether any macro other than the one you edited changed after logout
  (compare `macros list` before and after, or `diff` the file against the
  snapshot's copy);
- anything the client did that surprised you (a macro renamed, re-ordered,
  reset to a question-mark icon).

Nothing before section 3 writes through the Lab: the edit is yours, by
hand, on purpose, because this test is about what the client does with a
file the Lab did not write. The optional restore in section 3 goes through
the write gate like any `snap restore`, and `wowlab undo` reverses it. The
snapshot is there so the original always comes back. *Corrected
2026-10-18.*
