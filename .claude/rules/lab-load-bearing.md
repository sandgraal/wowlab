# Load-bearing files

Every tool stands on these. `luadata.py` reads the owner's data, and `guard.py` is the only thing allowed to change it. Those two are the load-bearing set (ADR-0013); `proposal.py` joins them when §16.5 F3 creates it (ADR-0013 amendment, accepted 2026-10-21), and the `[TEST]` / `[IMPL]` separation in `AGENTS.md` is mandatory for them. `svmerge.py` and `profiles.py` decide what `guard` writes back into the owner's files, and `wowlab_core.ui` (the `wowlab ui` server, ADR-0029, whether `ui.py` or a `ui/` package) opens a local port and runs CLI commands for the browser; they were in the set from 2026-09-29 and 2026-10-15 until the owner narrowed it on 2026-10-17. Their rules below still apply; their tests are the implementer's, graded by the reviewers. The bullets below that name `luadata.py` or `guard.py` apply to those files only.

- **Separation.** For `luadata.py` and `guard.py`, graders are written by `test-writer` and land on `main` first as `xfail(strict=True)`. Activate them by deleting the marker line only. Never edit a grader; if one is wrong, report it. A grader that already exists on `main` for another file in this list is activated the same way.
- **`luadata.py`: data, never code.** Tables, strings, numbers, booleans, nil. Reject functions, calls, metatables, operators and bare identifiers with a line and column. Bounded depth, size and string length; over a bound raises, never truncates, never lets a `RecursionError` escape.
- **`luadata.py`: fidelity.** Key order, key style, raw number text and trailing comments survive a parse. The serializer reproduces an unmodified real fixture byte for byte and is deterministic across platforms and locales. A fixture that cannot round-trip is a document-model finding, not a special case.
- **`guard.py`: no bypass.** Client closed or the write is refused; unknown counts as running. Allowlisted subtrees only. Snapshot first. Journal before and after hashes. Atomic replace. Roll back on any exception. No parameter, environment variable or private helper skips any of these.
- **`guard.py`: path handling.** Resolve before checking. Refuse traversal, absolute paths, symlink escapes, case-variant matches of forbidden paths, anything at the install root, `Data/`, executables, `.build.info`, `.flavor.info`.
- **Gate.** `make test-parser` green before you push a `luadata.py` change; the full suite (`make ci`) green before you push a `guard.py` change. `security-reviewer` reviews every `guard.py` diff and every `ui` diff.
- **`ui`: the local server (ADR-0029 and its 2026-10-15 and 2026-10-27 amendments).** Bound to `127.0.0.1` only; the opened URL carries only a one-time boot key, which opens nothing but `GET`/`HEAD /` and `POST /api/session` and is spent once under a lock; the session key on every other request, returned only in the body of that one exchange and never in a log, any other body, a header, a file, the address bar, or a child's argv or environment; `GET`/`HEAD /` with the spent boot key or with no query (a reload) answers a plain-text player sentence with no key, and every other refusal stays JSON; Host and Origin checked before a body is read or a key is looked at; no CORS; a CSP that allows only the server (plus `data:` fonts once ADR-0035's M16-51 lands), with `frame-ancestors 'none'`; from the UI, `sv dump` always runs with `--install-only`, measured against the install wowlab finds by itself; only Click-tree leaves run, argv built from declared parameters, never through a shell; every `--yes` command refused except through the confirm step of ADR-0029 (on `main` since M14-02, 2026-10-19: the plan run carries no `--yes`; a one-time confirm token, returned in that response and bound to the exact argv, is spent on first use; the confirmed argv is the plan argv with `--dry-run` removed and `--yes` added after `--json` and before any argument, plus, for `undo` and `sv merge` since M14-03, `--expect=<pin>` read from the plan's own report when the token is minted and never from the request; since M14-03 every `--yes` leaf is in the step, the shape read from what the leaf declares, and none stays refused), and `ui` itself, `looks page --out` and `log tail --follow` always refused; the subprocess is the running interpreter by absolute path (`sys.executable`), never a PATH lookup; a timeout that kills the whole process tree, and an output cap that bounds memory. The server writes nothing itself.
