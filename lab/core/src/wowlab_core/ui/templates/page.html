About this data

Every character folder in your game folder, in every flavor, as the lab-addon last saved it: at logout or /reload, never the session in progress. This tab reads with wowlab char list --summary. Pick a character to open it in the Character tab. A card's last played date is when the game last wrote that character's lab-addon file. Its gain (“+6 levels this week”) is shown when the newest save is from the last seven days: it compares that save with the last one before those days that your backups hold, or, when every save is from those days, with the first of them, and names that save's date when it is older than a week. The saves are read with wowlab char history, for the twelve characters played most recently, and only those played in the last seven days. The backup card is the backup line of the game shown in the header; the addons card counts what wowlab addons check finds current for that game. Names of races, classes and professions come from game tables wowlab names fetch downloads once per game version. A dimmed card is a character no longer in your game folder (a closed beta, a deleted folder) that one of your backups still holds: it shows that backup's newest save, read with wowlab char kept, and opens a page that changes nothing. A character folder with no lab record says so when one of your backups holds its record, and opens that page from it. Nothing is restored.

      About this data

      One character as the lab-addon last saved it: the file it wrote at logout or /reload, never the session in progress, beside the key bindings and macros the client last wrote, and its earlier saves that your backups hold. This page reads with wowlab char list, wowlab char gear, wowlab char binds, wowlab char macros and wowlab char history, or, for a character kept only in a backup, wowlab char kept, and, when you click Copy for WoWSims, wowlab char sim-export, and, when you ask the Twink panel, wowlab char twink. The one change it makes is to Your links: adding or forgetting one runs wowlab char link set or wowlab char link forget, which show their plan first and, on Confirm, write only wowlab's own links.json in its data folder, never the game folder. Nothing else runs. The professions are the ones wowlab char list --summary read for All characters. An item's name is its link's own text, and nothing is fetched, except that the Twink panel's first run for a game version downloads that version's item tables from wago.tools once. See it dressed opens an outside dressing room in your own browser, and only when you click it; this page makes no request to it. Copy for WoWSims shows the character as the text WoWSims' Addon Import reads, to copy and paste there yourself; wowlab sends nothing to WoWSims. The Twink panel's links and Your links open Wowhead, ForeverTwinking and Warcraft Logs the same way as See it dressed.

                  About this data

                  The crew book is the lab-addon's list of the players you grouped with, read with wowlab crew list; picking a player shows what wowlab crew show prints, and the match history is what wowlab crew matches prints. Seen by Spy reads the Spy addon's saved files with wowlab spy list, and picking a player there shows what wowlab spy show prints; nothing in Spy's files is changed. Names, guilds, notes, instance and map names are other people's text and are shown exactly as text, never as a link. Changing a rating or a note, or forgetting a player, runs wowlab crew rate, wowlab crew note or wowlab crew forget: each shows its plan first and changes nothing until you press Confirm; the game must be closed, a snapshot is taken first, and wowlab undo puts back what was there. Confirm runs only the plan shown: if the crew book's files changed after the plan, it is refused and nothing is written. For a player only wowlab's crew database keeps (the game's list dropped them), a rating or note changes that database alone: the plan says so, it cannot be undone, and Confirm is refused if their rating or note there changed after the plan.

                            About this data

                            Runs the commands of the wowlab you started, on this machine only. Reading never changes anything. Ten commands can change game files; each shows a plan and runs only when you confirm, after a snapshot. They are snap restore, undo, profile apply, sv merge, macros fix, addon install, addon remove, crew forget, crew rate and crew note, and wowlab undo reverses each of them. Six of them refuse to run when something changed after the plan: undo, when a newer change has been journaled; sv merge, macros fix, crew rate and crew note, when the file they change changed; and crew forget, when the crew book's file or the game's backup of it changed. The others apply what is there when you confirm, after the snapshot that wowlab undo restores from. The plan changes nothing; press Confirm under it to run the command for real. snap gc and doctor also ask first (--yes) and change only wowlab's own store. The commands that only read, or save only to wowlab's own data (snapshots, profiles, saved looks, the db2 cache, pages, extracted game files), run directly.

                            About this data

                            The page wowlab looks page writes: the races, body types, classes and customization options of the build's tables, and your saved looks checked against that build. Download tables and write the page runs that command. It downloads the build's public game tables from wago.tools when wowlab does not have them yet, sending your game version, then writes pages/looks.html in wowlab's own data folder, never touching your game folder, and shows that file here. The page itself runs in a closed frame: only its own script, no network requests, and nothing it can reach on this page.
